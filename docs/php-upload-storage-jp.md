# PHP アップロード先の安全な設定

`postFile.save` が生成する PHP は、保存前にアップロード先を `realpath` で解決し、次の条件を満たさない場合は保存を拒否します。

- 保存先が存在し、書き込み可能であること。
- POSIX 環境であり、保存先ディレクトリにグループ・その他ユーザーの権限がないこと（例: `0700`）。
- 保存先が生成 PHP の配置ディレクトリ、`DOCUMENT_ROOT`、または `AdditionalPublicDirectories` に指定された公開ディレクトリの内側でないこと。
- 保存後のファイルを `0600` に変更できること。変更に失敗したファイルは削除を試み、保存失敗として扱います。

```fsharp
let policy =
    { UploadPolicy.create "../private-uploads" 5_000_000L ["image/png", "png"] with
        AdditionalPublicDirectories = ["../public-assets"; "/srv/legacy-files"] }
```

保存先は Web 公開ルートの外に作成し、PHP を実行するユーザーだけがアクセスできるようにしてください。`AdditionalPublicDirectories` には Web サーバーの `alias` 等で公開される追加のディレクトリをすべて指定します。相対パスは生成 PHP の配置ディレクトリを基準とし、POSIX の絶対パスも指定できます。生成コードはサーバー設定を列挙できないため、このリストに漏れがある場合、非公開性を保証できません。

Web サーバー側でもアップロード領域への HTTP 直接アクセスと PHP/CGI 等のスクリプト実行を禁止してください。公開が必要なファイルは、認証・認可したダウンロード処理を通じて配信し、保存パスを直接公開しないでください。デプロイ時には、アップロード領域内のファイルへ直接 GET できず、スクリプトが実行されないことを実際のサーバーで確認してください。

この保護は POSIX の権限モデルを前提にしています。Windows 等では生成 PHP が保存を拒否します。別の権限モデルを使用する場合は、ACL と Web サーバー設定を検証できる実装を追加してから有効化してください。
